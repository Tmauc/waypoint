# @waypointjs/builder

An embeddable no-code UI for building and testing `WaypointSchema` objects. Drop it into any React or Next.js app.

```bash
pnpm add @waypointjs/builder @waypointjs/core
```

---

## \<WaypointBuilder\>

A self-contained editor component that renders a 3-column layout (step list, field list, step/field editors) and exports a `WaypointSchema`.

```tsx
import { WaypointBuilder } from "@waypointjs/builder";

<WaypointBuilder
  defaultValue={existingSchema}
  onChange={(schema) => console.log(schema)}
  onSave={async (schema) => {
    await fetch("/api/schemas", { method: "POST", body: JSON.stringify(schema) });
  }}
/>
```

### Props

| Prop | Type | Required | Description |
|---|---|---|---|
| `defaultValue` | `WaypointSchema` | | Initial schema to load |
| `onChange` | `(schema: WaypointSchema) => void` | | Called on every change |
| `onSave` | `(schema: WaypointSchema) => void \| Promise<void>` | | Called when user clicks "Save" |
| `theme` | `WaypointTheme` | | Custom theme (colors, fonts) |
| `className` | `string` | | CSS class on the root element |
| `style` | `React.CSSProperties` | | Inline style on the root element |
| `readOnly` | `boolean` | | Disable all editing — view-only mode |
| `appCustomTypes` | `CustomTypeDefinition[]` | | Custom field types — appear in the field type dropdown under "Custom" |
| `externalEnums` | `ExternalEnum[]` | | App-provided option lists — select/multiselect/radio fields can reference them by id |

### Layout

The builder renders in a **3-column layout**:

| Column | Content |
|---|---|
| Left | Step list + External Variables panel |
| Centre | Field list for the selected step |
| Right | Step editor (title, URL, conditions) + Field editor |

The builder requires explicit dimensions — set `height: 100%` on a sized parent or use `style={{ height: "100vh" }}` for full-screen.

Steps and fields can be reordered by drag & drop (desktop and mobile). Drag the handle to move items. Dependency constraints are enforced — invalid drops are rejected with an error message. Arrow buttons remain available as a fallback for keyboard and accessibility.

### Preview mode

Clicking **▶ Tester** in the toolbar switches to a **split view**:

- **Left panel** — resolved step list with status icons: `✓` done · `→` current · `○` upcoming · `–` hidden; and, if the schema declares `externalVariables`, an **External Variables** panel with mock value inputs (text, number, checkbox for boolean). Mock values sync immediately to the runtime store — conditions re-evaluate in real time.
- **Right panel** — live step renderer with field inputs, inline validation, progress bar, and Prev/Next navigation

Click **← Éditer** to return to the builder. The preview uses an isolated in-memory store — no localStorage, no side effects.

### Read-only mode

Pass `readOnly` to display a schema without allowing modifications:

```tsx
<WaypointBuilder defaultValue={schema} readOnly />
```

In read-only mode:
- All add/remove/duplicate/reorder controls are hidden
- All inputs in the step and field editors are disabled
- The toolbar shows only "Export JSON" + a "View only" badge
- Preview mode (`▶ Tester`) is disabled

### Theme

```ts
import { WaypointBuilder, DEFAULT_THEME, DARK_THEME } from "@waypointjs/builder";

// Pass a partial theme to override specific tokens
<WaypointBuilder
  theme={{ primary: "#6366f1", canvas: "#0f172a" }}
/>
```

Built-in themes: `DEFAULT_THEME`, `DARK_THEME`. All values are mapped to CSS custom properties at the root element.

## External Enums

External enums are app-provided option lists that you inject into the builder (and runner) at runtime. The schema stores only a **reference** (`externalEnumId`) — the actual values are never written to the schema JSON, which keeps schemas portable across environments.

### Defining enums

```tsx
import type { ExternalEnum } from "@waypointjs/core";

const externalEnums: ExternalEnum[] = [
  {
    id: "countries",
    label: "Countries",
    values: [
      { value: "fr", label: "France" },
      { value: "de", label: "Germany" },
      { value: "us", label: "United States" },
    ],
  },
  {
    id: "job_roles",
    label: "Job roles",
    values: [
      { value: "dev", label: "Developer" },
      { value: "pm", label: "Product Manager" },
    ],
  },
];

<WaypointBuilder externalEnums={externalEnums} ... />
```

### Using enums in the builder

Once injected, enums appear throughout the builder UI:

**Field options source** — For `select`, `multiselect`, and `radio` fields, the field editor shows an "Options source" dropdown. Selecting an enum replaces the hardcoded `options` array with `externalEnumId`. The field list shows a `⊞ label` badge.

**Condition builder (visibility)** — Every condition rule has an operator dropdown. Two special operators are available when enums exist:
- `is in enum` — the field's value must be one of the enum's values
- `not in enum` — the field's value must not be in the enum

The value input for these operators becomes a dropdown to select the target enum by name. For all other operators, a `⊞` picker button appears next to the text input to inject any enum value into the rule value field.

**Validation builder** — The same `is in enum` / `not in enum` rule types are available in the validation rules modal.

Comparator rules (equals, greaterThan, etc.) support a **field reference** mode. Click the toggle button to switch between a static value and a reference to another field in the journey. When in field reference mode, the value is resolved from journey data at validation time.

### Passing enums to the runner

Use the same array with `WaypointRunner` so enum-based conditions and validations evaluate correctly at runtime:

```tsx
<WaypointRunner schema={schema} externalEnums={externalEnums}>
  {children}
</WaypointRunner>
```

And pass it to `buildZodSchema` when building Zod schemas manually:

```ts
const zodSchema = buildZodSchema(fields, externalEnums);
```

## Dynamic defaults

Each field supports **dynamic defaults** — conditional default values evaluated at tree resolution time. In the field editor, click "Add rule" under "Dynamic defaults" to define rules with conditions and values. The first matching rule wins; if none match, the static `defaultValue` is used.

See [DynamicDefaultRule](/api-reference/core#dynamicdefaultrule) in the core API reference for the programmatic interface.

## Custom Types

Custom types are app-specific field types that extend the built-in set (`text`, `select`, `number`, etc.). They appear in the field type dropdown under a **Custom** optgroup. When selected, their `defaultValidation` (if defined) is auto-applied to the field.

### Defining custom types

```tsx
import type { CustomTypeDefinition } from "@waypointjs/core";

const appCustomTypes: CustomTypeDefinition[] = [
  {
    id: "rich-text",
    label: "Rich Text",
    icon: "📝",
    defaultValidation: [{ type: "required", message: "Content is required" }],
  },
  {
    id: "date-range",
    label: "Date Range",
    icon: "📅",
  },
  {
    id: "file-upload",
    label: "File Upload",
    icon: "📎",
    metadata: { accept: "image/*,application/pdf" },
  },
];

<WaypointBuilder appCustomTypes={appCustomTypes} ... />
```

### Using custom types at runtime

The `type` value is stored as-is in the schema. When rendering fields, check for custom types and delegate to your own renderer:

```tsx
// With @waypointjs/next:
<WaypointRunner schema={schema} customFieldTypes={appCustomTypes}>
  {children}
</WaypointRunner>

// In your step page, check field.definition.type:
{fields.map((field) => {
  const isCustom = appCustomTypes.some((t) => t.id === field.definition.type);
  if (isCustom) return <MyCustomField key={field.definition.id} field={field} />;
  // ... standard fields
})}
```

### CustomTypeDefinition

```ts
interface CustomTypeDefinition {
  id: string;                        // stored as field.type in the schema
  label: string;                     // shown in the type dropdown
  icon?: string;                     // displayed in the builder UI
  defaultValidation?: ValidationRule[]; // auto-applied when the type is selected
  metadata?: Record<string, unknown>; // passed through to your runtime renderer
}
```

## useBuilderStore

Access the builder's internal Zustand store for programmatic control.

```ts
import { useBuilderStore } from "@waypointjs/builder";

const { schema, loadSchema, isDirty, resetSchema } = useBuilderStore();
```

### Useful methods

| Method | Description |
|---|---|
| `loadSchema(schema)` | Load a schema into the builder |
| `resetSchema()` | Reset to the empty default schema |
| `addStep(partial?)` | Add a step, returns new step ID |
| `updateStep(stepId, updates)` | Update step properties |
| `removeStep(stepId)` | Remove a step |
| `duplicateStep(stepId)` | Clone step with new IDs, insert after original |
| `reorderSteps(from, to)` | Reorder steps by index |
| `addField(stepId, partial?)` | Add a field to a step, returns new field ID |
| `updateField(stepId, fieldId, updates)` | Update field properties |
| `removeField(stepId, fieldId)` | Remove a field |
| `duplicateField(stepId, fieldId)` | Clone field with new ID, insert after original |
| `reorderFields(stepId, from, to)` | Reorder fields within a step |

<Callout type="warning">
  `useBuilderStore` is a singleton — there can only be one builder instance per page. For multiple builders, you'd need to isolate each in its own React root.
</Callout>

## Embedding in Next.js

```tsx
// app/admin/builder/page.tsx
"use client";

import { WaypointBuilder } from "@waypointjs/builder";
import { useRouter } from "next/navigation";

export default function BuilderPage() {
  const router = useRouter();

  return (
    <div style={{ height: "100vh" }}>
      <WaypointBuilder
        onSave={async (schema) => {
          const res = await fetch("/api/journey-schemas", {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify(schema),
          });
          if (res.ok) router.push("/admin/journeys");
        }}
      />
    </div>
  );
}
```

## Loading an existing schema

```tsx
"use client";

import { WaypointBuilder } from "@waypointjs/builder";
import { useEffect, useState } from "react";
import type { WaypointSchema } from "@waypointjs/core";

export default function EditSchemaPage({ params }: { params: { id: string } }) {
  const [schema, setSchema] = useState<WaypointSchema | undefined>();

  useEffect(() => {
    fetch(`/api/journey-schemas/${params.id}`)
      .then((r) => r.json())
      .then(setSchema);
  }, [params.id]);

  if (!schema) return <div>Loading…</div>;

  return (
    <div style={{ height: "100vh" }}>
      <WaypointBuilder
        defaultValue={schema}
        onSave={async (updated) => {
          await fetch(`/api/journey-schemas/${params.id}`, {
            method: "PUT",
            body: JSON.stringify(updated),
          });
        }}
      />
    </div>
  );
}
```
